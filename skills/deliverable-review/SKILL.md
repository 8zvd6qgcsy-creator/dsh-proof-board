# 交付物质检：先自己过一遍，再交给用户

质检不是"再看一眼"，是按清单逐项打勾。发现问题就写成审阅台批注（`fix` + 一句话），
用户打开侧栏「审阅台」能直接看到问题清单，不用在对话里翻。

## 先看真东西

- PPT / 文档 / 表格：不要只读 XML 就下结论。用 `office_render`（需要先加载 office skill）或让用户台上的缩略图说话。
- 网页 / HTML 演示：用浏览器工具截图，或者看审阅台上的实时预览。
- 图片：`read_image` 真的看一眼，别只看尺寸。

## PPT / 演示

1. **溢出**：任何一页的标题、正文、图注超出安全区（左右各留 8%、底部 10%）。
2. **撞车**：文字压到图上、两个元素重叠、页脚和正文打架。
3. **字号层级**：逐级递减清楚（主标题 > 小标题 > 正文 > 注释）；正文小于 14pt 在投影上看不清。
4. **图片**：清晰度够不够（拉伸后糊不糊）、比例有没有拉变形、截图里有没有露出与内容无关的界面。
5. **留白**：四周留白是否一致；塞满一页和空一半都是问题。
6. **数据**：同一组数字在不同页是否一致；单位、百分比基准、时间口径。
7. **文字**：错别字、全角半角混排、中英之间缺空格、标点用了英文半角。
8. **一致性**：配色不超过 3 个主色；同层级标题字号字重统一；页码 / 页眉风格统一。

## 文档

1. 标题层级连续（不能跳级）；目录和正文标题对得上。
2. 表格不跨页断裂、列宽不挤字、数字右对齐。
3. 图注编号连续；正文里提到的"如下图"真的存在。
4. 页眉页脚、页码、落款日期正确。

## 表格

1. 公式列和手工列不混用；合计行有公式不是死值。
2. 列宽能看清数字；日期格式统一；空单元格是真的空，不是空格。
3. 冻结窗格、筛选、条件格式没有破坏原有内容。

## 网页 / 卡片

1. 移动端宽度（375 / 390）不横向溢出；字号在手机上可读。
2. 图片有 alt；链接可点；没有指向本地绝对路径的资源。
3. 深浅色主题都能看（如果支持）。

## 写批注的格式

- 一条一个动作，带位置：`第 4 页`、`第三节表格`、`封面副标题`。
- 说清怎么做：`统一改成 0.6 倍行距`，不要只说"间距不对"。
- 没把握的写 `todo`，别猜成 `fix`。

## 交付前最后一步

1. 改完的文件重新扫一遍：`proof_board_scan`，确认被改的那几项 mtime 更新了。
2. 把改完的标 `ok`，没改的留 `fix` 并说明原因。
3. 只有用户能签"通过"。agent 的 `ok` 意思是"我这边的检查项都过了"，不是"用户可以收下了"。
